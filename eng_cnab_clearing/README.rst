This module changes how a CNAB return file settles the boletos of a bank
journal, so that the bank statement becomes the only source of the bank
account.

For a journal with the **CNAB Clearing Flow** enabled, each liquidation
credited on or after the **Bank Cutover Date** is settled by one journal
entry that:

- is dated on the **occurrence date** (the day the customer paid), not
  on the credit date nor on the import date;
- debits a single **clearing account** line with the received amount,
  due on the **credit date** and tagged with the class of the receiving
  bank (own bank or other banks), where the bank statement line of that
  credit date will reconcile it;
- keeps the installment line (reconciled with the invoice as before) and
  the interest, discount and rebate lines in their result accounts;
- has no line in the bank account of the journal and no tariff line: the
  tariff stays on the CNAB return event, and the bank statement is the
  only source of bank tariffs.

The whole return file is validated before any record is processed. The
file is refused, with the file name, the sequence number of each faulty
record (or, for a record without one, its position among the records
read from the file) and the reason, when a detail record has no valid
occurrence date (no fallback to the credit date or to today), when a
liquidation has no valid credit date, or when an Ailos liquidation does
not state the receiving bank.

The module also:

- links every event, entry and clearing line to the position of its
  record in the file;
- refuses a file already imported in the same journal (SHA-256 of the
  file, unique per company and journal);
- refuses to post a clearing entry when a lock date would replace its
  occurrence date, also when a draft entry is posted later, and cancels
  the posting when any module changes that date while posting.

Liquidations credited before the cutover date, and journals without the
clearing flow, keep the original import of
``l10n_br_account_payment_brcobranca``.

Configuration
=============

1. Create the clearing account of the bank: a current asset account of
   the company of the journal, which allows reconciliation and is not
   the bank account of the journal.
2. Open the bank journal (Invoicing > Configuration > Journals), tab
   **Import related infos**, and:

   - enable **CNAB Clearing Flow**;
   - set the **Bank Cutover Date**: liquidations credited on or after it
     use the clearing flow, the older ones keep the legacy flow;
   - pick the **CNAB Receipt Method**, an inbound payment method of the
     journal whose **Outstanding Receipts** account is the clearing
     account. The account must be set on the method itself: the default
     account of the company is not used as a fallback.

3. Point the other inbound payment methods of the journal to the same
   clearing account, so that manual receipts are reconciled by the bank
   statement as well.

The clearing flow supports Banco do Brasil CNAB 400 and Ailos CNAB 240
return files only. Any other layout needs its own tests first.

Usage
=====

Import the CNAB return file as usual, from the journal (**Import batch
file**). For the liquidations credited on or after the cutover date:

- the invoice is paid on the occurrence date of the return;
- the clearing line waits for the bank statement line of its credit
  date, with the receiving bank class on it;
- the return log shows the journal and the hash of the file, and each
  event shows its position in the file, the receiving bank and the
  clearing entry.

When the file is refused, nothing is imported: no log, no attachment, no
event, no entry and no CNAB state change. Ask the bank for a corrected
file, or review the lock date with the accounting team, and import it
again.

With **Automatic Reconcile payment returns** disabled on the journal,
the clearing entries stay in draft; posting them later goes through the
same lock date protection.

Known issues / Roadmap
======================

- Support other return layouts, each with its own tests: Itau CNAB 400
  returns the received amount net of the tariff, and the Sicoob CNAB 240
  dates have their own format.
- The reconciliation of the clearing lines with the bank statement is
  the job of a separate module.
